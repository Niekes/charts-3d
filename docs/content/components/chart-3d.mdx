## Renderers

The marks of a chart - its bars, points and faces - are drawn by the renderer of the container. `"svg"`, the default, draws them as SVG elements; `"canvas"` paints them on a canvas, for charts with many marks.

```tsx
<ChartContainer3D config={chartConfig} renderer="canvas">
```

The box, its labels, the tooltip, the legend and the gizmo stay SVG and HTML with every renderer. A chart draws as SVG on the server and until the browser shows it has a canvas, and stays SVG where it has none.

## Shortcuts

Press `?` on a chart, or the keyboard button in its corner, for the shortcuts that rotate, pan, zoom and reset it. `shortcuts={false}` hides the button. The chart announces its keys to screen readers through `aria-keyshortcuts`, and the keys in the panel carry `data-slot="kbd"`, as the Kbd of shadcn/ui does, so `className="[&_[data-slot=kbd]]:bg-background"` on the container restyles them. The button is `data-slot="chart-3d-shortcuts-trigger"`, the list `data-slot="chart-3d-shortcuts"`.

### Keymap

`keymap` rebinds, renames or turns off every action, over its defaults. Keep it outside the component, so it stays the same object between renders.

```tsx
const keymap: Keymap3D = {
  rotateLeft: ["a", "ArrowLeft"], // new keys; the panel shows the first
  zoomIn: { keys: ["Control+Plus"], label: "Vergrößern" },
  reset: false, // the action is off
  wheelZoom: false, // so is the gesture, and Ctrl with the wheel zooms the page
  help: { label: "Tastenkürzel" }, // the name of the button and of its row
}

<ChartContainer3D config={chartConfig} keymap={keymap}>
```

`keymap={false}` turns everything off: the chart stands still, leaves the tab order and shows no button. The panel lists the actions that are on, one row per label, so actions that share a label share a row.

| Action             | Default keys            | Label              |
| ------------------ | ----------------------- | ------------------ |
| `dragRotate`       | Drag                    | Rotate             |
| `rotateLeft`       | `ArrowLeft`             | Rotate             |
| `rotateRight`      | `ArrowRight`            | Rotate             |
| `rotateUp`         | `ArrowUp`               | Rotate             |
| `rotateDown`       | `ArrowDown`             | Rotate             |
| `dragPan`          | Space and drag          | Pan                |
| `panLeft`          | `Shift+ArrowLeft`       | Pan                |
| `panRight`         | `Shift+ArrowRight`      | Pan                |
| `panUp`            | `Shift+ArrowUp`         | Pan                |
| `panDown`          | `Shift+ArrowDown`       | Pan                |
| `zoomIn`           | `Plus`, `=`             | Zoom               |
| `zoomOut`          | `-`                     | Zoom               |
| `wheelZoom`        | Ctrl or ⌘ and the wheel | Zoom               |
| `reset`            | `0`                     | Reset              |
| `doubleClickReset` | Double-click            | Reset              |
| `help`             | `?`                     | Keyboard shortcuts |

Keys are written the way `aria-keyshortcuts` writes them: the modifiers `Control`, `Alt`, `Meta` and `Shift`, then the [`key`](https://developer.mozilla.org/en-US/docs/Web/API/KeyboardEvent/key) of the press, joined by `+`, with `Plus` for the plus key and `Space` for the space bar. A press matches only with exactly the modifiers of its keys, so Ctrl and `0` still resets the zoom of the browser. Shift counts beside a named key such as `ArrowLeft`; a character such as `?` is typed with it already, so `"?"` matches without it. The gestures can be turned off and renamed, but not rebound.

The keys work only while the chart has the focus, and every one can be turned off or rebound, as [WCAG 2.1.4](https://www.w3.org/WAI/WCAG22/Understanding/character-key-shortcuts.html) asks of shortcuts with a single character.

## Gizmo

The axes in the lower left corner turn with the camera, so a turned chart still shows which way is up and where its axes point. They neither pan nor zoom. `gizmo` moves them to another corner, `gizmo={false}` hides them.

```tsx
<ChartContainer3D config={chartConfig} gizmo="top-left">
```

The gizmo is `data-slot="chart-3d-gizmo"`, drawn in `--muted-foreground` and hidden from screen readers. Each axis draws in `currentColor` and carries `data-axis`, so `className="[&_[data-axis=x]]:text-red-500"` on the container colors one axis.

## Focus

A mark or a label can name the groups it belongs to in `groups`. While the pointer is on a mark, every mark and label that shares none of its groups fades to a quarter of its color. The marks fade in place, so the order they paint in, and with it the depth, stays as it was, on the canvas too. Off the marks and while a drag turns the chart the focus stays, so what is in focus can be followed from every side; leaving the chart ends it. Marks without groups never fade.

```tsx
// The faces of a flow share its key; the faces of a node carry the keys of all its flows.
const marks = faces.map((face) => ({ ...face, groups: [flow.key] }))
```

## Labels

The labels of the box sit beside their ticks, away from the box, and slide round them as the camera turns. Where two would touch, they slide apart along their axis, and where that is not enough, every other one moves to a second row; only an axis seen nearly end on shows every second, fourth… label. A label gives way to one of an axis with fewer ticks, whose labels say more each. When an axis moves to another edge of the box, its labels fade from one edge to the other.

The arrow keys glide the camera to its next view instead of jumping there. Where the reader asks for reduced motion, the camera jumps and the labels move without a transition.
